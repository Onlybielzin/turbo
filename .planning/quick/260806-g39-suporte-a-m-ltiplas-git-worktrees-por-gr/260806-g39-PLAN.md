<objective>
Adicionar suporte a múltiplas git worktrees por grupo no Turbo: detectar worktrees existentes, criar novas, roteá-las como raias no GroupFrame, abrir terminais/agentes com cwd = worktree, garantir `.mcp.json` dentro de cada worktree que hospeda agente, e fazer `spawn_agent` herdar a worktree do pai.

Purpose: hoje um grupo = um único cwd (raiz do repo) e o `.mcp.json` só existe lá. Um `claude` rodando dentro de uma worktree (`.claude/worktrees/<x>`) não acha o MCP, e não há como isolar trabalho por branch dentro do mesmo grupo. Este plano resolve isso reaproveitando a lógica de registro/`.mcp.json` existente.

Output: módulo Rust `worktrees.rs` com 3 comandos Tauri; propagação de worktree via env no `spawn_agent`; estado de raia no store; UI de raias no GroupFrame.
</objective>

  <name>Task 1: Comandos Tauri de worktree (list / create) + `.mcp.json` por worktree em Rust</name>
  <files>app/src-tauri/src/worktrees.rs, app/src-tauri/src/lib.rs, app/src-tauri/src/groups.rs</files>
  <action>
    Crie o módulo `app/src-tauri/src/worktrees.rs` com uma struct serializável `Worktree { path: String, branch: String, is_root: bool }` e três comandos Tauri, todos usando `std::process::Command` chamando `git` (nunca rodar git no front — WT-01).

    (1) `list_worktrees(cwd: String) -> Result<Vec<Worktree>, String>`: executa `git -C <cwd> worktree list --porcelain`, faz o parse dos blocos (`worktree <path>`, `branch refs/heads/<name>`; bloco sem `branch` = detached → use o hash de `HEAD <sha>` abreviado como branch). Marque `is_root=true` o item cujo path canônico é igual ao cwd raiz do grupo (o primeiro item do porcelain é sempre a worktree principal). Se o cwd não for um repo git (`git` retorna status != 0), retorne `Ok(vec![])` — o grupo simplesmente não tem raias além da raiz (o chamador trata isso como "só a raiz").

    (2) `create_worktree(cwd: String, name: String, branch: String, new_branch: bool) -> Result<Worktree, String>`: valida `name` (não vazio; rejeite se contiver `/`, `..` ou separador de path — usar apenas `[A-Za-z0-9._-]`, senão `Err`). Computa `path = <cwd>/.claude/worktrees/<name>`. Cria o diretório-pai `.claude/worktrees` se faltar (`std::fs::create_dir_all`). Roda `git -C <cwd> worktree add <path> -b <branch>` quando `new_branch=true`, ou `git -C <cwd> worktree add <path> <branch>` quando `new_branch=false` (branch existente). Propaga stderr do git no `Err(...)` em falha. Em sucesso retorna o `Worktree` criado (`is_root=false`).

    (3) `ensure_worktree_mcp(cwd: String, group_id: String, mcp_port: u16) -> Result<(), String>`: idempotente — garante que `<cwd>/.mcp.json` exista com o MESMO conteúdo/URL do grupo. Para evitar duplicar a serialização, adicione em `groups.rs` uma função pública `write_mcp_json(cwd: &Path, group_id: &str, mcp_port: u16) -> Result<String, String>` extraída do corpo atual de `GroupRegistry::register` (o bloco que monta o `json!` e escreve `.mcp.json`), e faça `register` chamá-la. `ensure_worktree_mcp` chama essa mesma `write_mcp_json`. Isso mantém uma única fonte de verdade para o formato `.mcp.json` (type "http", url `http://127.0.0.1:{port}/mcp?group_id={group_id}`).

    Em `lib.rs`: adicione `mod worktrees;`, registre os três comandos em `tauri::generate_handler!` (junto de `create_group`, etc.). Não altere a assinatura de `create_group` — ele continua escrevendo `.mcp.json` no `cwd` que recebe (que passará a ser o path da worktree ativa vindo do front na Task 3).

    Siga os padrões do repo: `#[tauri::command]`, `Result<_, String>` com `.map_err(|e| e.to_string())`, structs `#[derive(serde::Serialize)]`, `tracing::info!` nos pontos-chave (worktree criada, `.mcp.json` escrito). Sem `unwrap()` fora de locks já existentes.
  </action>
